# E8 Ladder Diagram

## File structure

- `original/` is an untouched copy of the submitted Beremiz project.
- `repaired/` corrects the missing physical I/O addresses and changes `CV4`
  from an input to an output.
- `generated/` contains Structured Text and the variable table generated by the
  submitted project. These files make the implemented logic reviewable without
  committing platform-specific binaries.

## Evidence-backed I/O mapping

| Variable | Direction | Address |
| --- | --- | --- |
| `S_MILL` | Input | `%IX0.7` |
| `S_DRILL` | Input | `%IX1.1` |
| `CV1` | Output | `%QX0.4` |
| `CV2` | Output | `%QX0.5` |
| `CV3` | Output | `%QX0.7` |
| `CV4` | Output | `%QX1.1` |

The mapping comes from the original E8 submission. It was not saved in the
submitted PLCopen XML, so it has only been applied to the separate repaired
copy.

## Known limitations

- The submitted evidence shows that the original logic compiled and was uploaded
  to OpenPLC Runtime.
- FTsim was not available during the original submission, so the sequence was
  not validated against the simulated production line.
- The generated logic sets `M_TO_DRILL` and `M_TO_EXIT` from timers, but those
  states do not currently affect the conveyor logic. This must be reviewed
  before claiming functional sequence control.
- The repaired XML must be opened and rebuilt in Beremiz/OpenPLC before a new
  runtime binary is distributed.

The original files are retained unchanged so the repair remains auditable.
